# 赤壁之战原始证据资料池 v1

## 这一步解决什么

本批次先把与赤壁脉络有关的原文装进可追溯的证据池，不把“书中一句话”直接变成事件卡。入库对象依次是：作品、保存载体、数字资产、篇章节点、文本版本、原文锚点和原作归属。

资料包本身也作为一等对象入库：每一版清单都有不可变的清单校验值、传本文档成员关系、来源家族、必需状态和覆盖角色，并另设当前启用版本指针。这样后续补书或换底本时新增版本，不覆盖旧清单。当前启用清单为 `1.1.0`，共收 17 个传本文档；旧版清单和旧导入批次仍保留。

资料池与事件层严格隔离：本批次不会生成来源陈述、规范命题、事件候选、正式事件或页面发布记录。待原文覆盖和传承关系审完后，再由人工定义赤壁事件簇及阶段边界。

“17 个传本文档”不等于“17 条独立证据”。散佚作品经裴注、类书或地方文献保存时，数据库分别记录原作品和保存载体，并通过作品关系、节点归属和后续传承组审查避免重复计证。地理志材料只是不同年代的行政地理切片，不能单独裁决赤壁战场的现代位置。

## 原文层收录规则

- 只收能精确定位到书、卷、篇章或条目的古籍原文；现代论文、网页解说和《三國演義》不进入原文层。
- 正文、注引、类书转引分别保留，不把宿主作品和被引原作默默合并。
- 同一佚文出现于多个保存载体时保留各自文字异同，但后续计证必须先归入传承组，不能按出现次数加权。
- 保留底本文字和重要异文，不为迎合既有事件叙事而擅自统一人名、地名、纪年或胜负归属。
- 只收与战前因果、联盟决策、战斗与撤退、紧接战后处置或空间边界直接相关的段落；一般人物生平和遥远后果暂不扩张。
- 原文入池不等于事件成立。任何来源陈述、规范命题和事件边界仍须在下一阶段逐条审核。

## 1.1.0 入库审计摘要

- 当前启用资料包：17 个来源家族 / 17 个传本文档 / 27 个作品身份。
- 当前资料包见证：164 个篇章节点、104 个文本版本与原文锚点、30 个显式原作归属。
- 主库保留《三國志》上一版数字资产和导入批次，因此资产与导入批次总数各为 18；活动传本仍为 17，旧记录没有被覆盖。
- 旧 `events` 表保持 1678 条不变；来源陈述候选、规范命题候选、事件候选、正式事件与发布记录均为 0。
- 外键检查为 0，全部资产地址均为 `repo:data/evidence-pool/...`，可由迁移和 Seed 在新数据库中复现。

## 当前文本边界

- 保存基础文言原文和定位信息；暂不把现代译文混入原文层。
- 现有数字文本标记为研究转写，尚未宣称逐页影像校勘完成。
- 权利策略为内部保存，可引用性按清单记录，但默认禁止公开全文展示与全文索引。
- 全部资产使用 `repo:data/evidence-pool/...` 逻辑地址，Seed 不包含本机绝对路径。

## 可复现流程

```powershell
npm run plan:red-cliffs-source-pool
npm run build:red-cliffs-source-pool-db
npm run audit:red-cliffs-source-pool:shadow
npm run test:red-cliffs-source-pool
```

影子库验收后，才允许显式写入主库：

```powershell
npm run apply:red-cliffs-source-pool:main
npm run audit:red-cliffs-source-pool
npm run db:seed:export
npm run validate:db
```

正式写入仍只触及原始证据池。`db/chronoatlas.sqlite` 是本地产物；跨电脑复现依靠迁移文件、资料清单和 `db/seeds`。
