# 190-310 范例时期标准

## 定位

`190-310 CE` 是 ChronoAtlas 的第一个正式范例时期。后续每个成熟时间段都应复用这套结构：世界总览、区域地图、人物、事件、年龄对比、史料证据、证据图谱、RAG 评测和覆盖度检查。

这个时期的目标不是把所有史料穷尽，而是形成一个可复制的学习与数据模板：

- 地图能表达同一年份下中国、罗马、萨珊的粗略格局。
- 区域详情能进入郡县、省份、控制区或事件详情。
- 人物、事件、年龄对比、事件对比、史料证据能互相跳转。
- 关键判断能追溯到 SQLite 里的来源、原文、译文、证据链接和争议说明。
- AI/RAG 默认优先使用数据库证据，外部资料只能作为少量通识补充并明确标注。
- 前端只保存视图状态和布局，正式史料、地图控制、证据、事件分级都进入 SQLite/API。

## 区域分级

| 层级 | 区域 | 标准 |
|---|---|---|
| Core | 中国 | 三国到西晋统一主线必须完整：核心事件、人物、生卒年、郡县地图、正史证据。 |
| Core | 罗马 | 塞维鲁王朝、三世纪危机、奥勒良重合一、戴克里先改革和四帝共治必须形成完整线索。 |
| Core | 萨珊波斯 | 阿尔达希尔、沙普尔一世、纳尔塞、罗马-萨珊战争、铭文/钱币/古典叙事证据必须可查。 |
| Context | 印度、草原、印度洋贸易 | 只做背景或小框，不与中国、罗马、萨珊同级。证据不足时必须明确说明低置信度。 |

## 页面结构标准

每个成熟时期至少提供这些页面或等价入口：

- 首页总览：大时间条、世界粗略地图、时期入口、核心区域位置。
- 学习模式：把地图、事件、人物、史料、AI 问答和覆盖度检查串成一条学习路径。
- 区域详情：区域地图、控制时间线、事件筛选、选中区域详情。
- 人物索引：人物卡、势力筛选、人物详情、生平节点。
- 年龄对比：同一年不同人物年龄，可跨区域筛选。
- 事件对比：同一年或相邻年份的核心区域事件并列。
- 史料证据：按人物、事件、来源、地区检索证据卡。
- 证据图谱：展示断言、来源、人物、事件之间的结构化关系。
- 覆盖度检查：显示事件、人物、证据、原文和地图缺口。
- RAG 评测：显示问题集、命中证据、分数、失败原因和检索路径。

## 数据最低标准

190-310 当前达标线按三个核心区域分层，不要求每个区域同等密度：

| 指标 | 中国 | 罗马 | 萨珊 |
|---|---:|---:|---:|
| 事件 | >= 250 | >= 150 | >= 20 |
| 人物 | >= 120 | >= 30 | >= 5 |
| 事件证据链接 | >= 300 | >= 150 | >= 25 |
| 证据断言 | >= 20 | >= 35 | >= 5 |

全局标准：

- RAG 评测题：>= 60。
- 最近一次 RAG 评测失败数：0。
- 最近一次 RAG 评测均分：>= 0.95。
- 190-310 地图控制记录：>= 1000。
- `source_id / locator / original_text 或 quote / translation 或 interpretation / involved persons / involved events / year / confidence / dispute_note` 应尽量齐全。

实际验收以 `npm run audit:period-190-310` 为准。

## 事件分层

事件必须分层，否则首页和地图会拥挤。

| 层级 | 用途 | 显示位置 |
|---|---|---|
| major | 改变区域格局的大事件 | 首页、时期地图、事件对比默认显示 |
| medium | 重要但局部的政治、军事、继承事件 | 区域详情、事件对比开启中型事件后显示 |
| detail | 年表补充、局部人物动作 | 详情面板、人物页、史料页 |
| life | 人物生平节点 | 人物页、年龄对比引用 |

每条正式事件至少需要：

- `id`
- `region_id`
- `period_id`
- `title`
- `time_start`
- `time_end`
- `event_type`
- `importance`
- `summary`
- `confidence`
- `related_entity_ids`
- `source_refs` 或 `evidence_links`

## 史料证据标准

史料证据卡是后续 AI/RAG 的基础。每条证据尽量关联：

| 字段 | 要求 |
|---|---|
| `source_id` | 指向 `sources.id`。 |
| `locator` | 卷、篇、章、铭文段落、页码或编号。 |
| `original_text` / `quote` | 原文或可核验摘录；没有原文时必须说明。 |
| `translation` / `interpretation` | 中文译文、释义或摘要；不能替代原文。 |
| `year` | 事件年份；不确定时允许为空，但要写争议说明。 |
| `mentioned_people` | 人物 ID 或导入时可解析的人名。 |
| `mentioned_events` | 关联事件 ID 或事件标签。 |
| `mentioned_places` | 地名、郡县、省份、城市或战场。 |
| `confidence` | `high`、`medium`、`low`。 |
| `review_status` | `draft`、`staged`、`reviewed`。 |
| `dispute_note` | 年份、文本传承、后世追述、二手文献依赖等争议说明。 |

示例：

```json
{
  "id": "evidence:period-190-310:cao-cao-death",
  "source_id": "sanguozhi-wei-wudi",
  "source_title": "三国志·魏书·武帝纪",
  "locator": "建安二十五年",
  "original_text": "庚子，王崩于洛阳，年六十六。",
  "translation": "曹操于建安二十五年正月庚子在洛阳去世，年六十六。",
  "year": 220,
  "mentioned_people": ["person:cao-cao"],
  "mentioned_events": ["china-220-cao-cao-death"],
  "mentioned_places": ["luoyang"],
  "confidence": "high",
  "review_status": "reviewed",
  "dispute_note": null
}
```

## SQLite/API 标准

必须进入 SQLite/API 的数据：

- 事件、人物、人物关系、生平节点。
- 来源书目、原文段落、译文、证据链接。
- 证据断言、断言来源、断言主体、断言关系。
- 地图几何、地图控制时间线、控制者、来源说明。
- 首页总览时期配置、事件展示分级、覆盖度配置。
- RAG 问题、RAG run、RAG result、AI answer 和召回证据。

可以保留在前端的内容：

- 纯 UI 布局状态。
- 临时筛选状态。
- 视觉尺寸、颜色、交互状态。

不要进入仓库或正式 seed 的内容：

- `demos/` 临时实验。
- DeepSeek 原始长输出。
- 本地下载 PDF、扫描件、参考资料原件。
- 未审校的批量草稿。

## 验收命令

每次把 190-310 当作范例期交付前，至少运行：

```bash
npm run audit:period-190-310
npm run validate:db
npm run run:rag-eval
npm run build
```

`npm run audit:period-190-310` 只读 SQLite，不调用模型，不修改数据库；它负责判断模板期基础量级是否达标。

## 后续时期复用流程

1. 定核心区域和次重点区域。
2. 定时期边界、关键年份和首页时期卡。
3. 先导入 major 事件，再导入 medium/detail。
4. 先挂事件证据，再补人物生平证据。
5. 地图几何和控制时间线进入 SQLite/API。
6. 建证据断言和断言来源。
7. 做覆盖度检查页。
8. 做 30 题 RAG 初评，再扩到 60 题。
9. 评测失败项归零后，才把该时期标记为正式范例。

- 萨珊：27 条事件、7 个人物实体、52 条事件证据链接、6 条证据断言。
- 190-310 地图控制记录：1280 条。
- RAG 评测题：60 题。
- 最近一次 RAG 评测：60/60，通过率 100%，均分 0.9802。

这个状态可以作为“模板期”继续使用，但后续仍可以增强：

- 罗马和萨珊的英文内容完整度。
- 罗马省份地图的正式来源标注。
- 萨珊人物和铭文证据的细颗粒度。
- 中国郡县几何的正式来源和版本管理。
